ZenOut Labs develops tools for the everyday work between spreadsheets, inboxes, and business software: organizing information, connecting routine tasks, and making the next decision clearer.

Our focus is practical: start with a specific problem, build something people can use, and make its behavior understandable.

### What we're building

| Area | The work |
| :--- | :--- |
| **Workflow automation** | Follow-up queues, information handoffs, and repeatable business processes. |
| **Internal tools** | Dashboards, research workspaces, and interfaces for reviewing records and exceptions. |
| **Clear handover** | Setup instructions, documented checks, and visible limits so the next person can understand the system. |

### Selected work

- **[Automation proof notebook](https://github.com/zenoutlabs/automation-proof)** — recorded fictional-data n8n demonstrations, a reusable acceptance checklist, and checks readers can run. External services are simulated; this is not the commercial workflow pack.
- **[Salam BOMCheck](https://github.com/zenoutlabs/salam-bomcheck)** — a small offline utility that finds mistakes in an electronics parts list. Built in Salam, with Python-driven tests.

### How we build

We use AI-assisted development, documented checks, and clear project scope. Each public project should explain what it does, how to try it, and its current limitations. Demonstrations use sample data; prototypes are labeled as prototypes. Websites and interfaces support the workflow around them.
